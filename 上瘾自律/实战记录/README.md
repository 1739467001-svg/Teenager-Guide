# 实战记录 · 知识库第 4 层

> 前三层是**推演**出来的：书里说了什么 → 我们判断什么 → 我们做了什么。
> 这一层是**撞**出来的：真的开课之后，现场把哪几处设计打了回来。
>
> **当第 4 层和第 3 层冲突时，以第 4 层为准。**

## 记录纪律

沿用整个知识库的同一条方法论签名：

1. **只记发生了什么，不美化。** 「Day2 压到 1.5 小时」照写，不写成「灵活调整」。
2. **不确定的一律标「待确认」，不补写。** 到场几个孩子记不清就写「约 4 个（待确认）」，不要凑一个数。
3. **区分「改对了」和「被迫改」。** 前者要固化进下一版，后者要在下一版里补上防线——两者混在一起，下一版就会把临场救火当成设计。

## 命名

```
YYYY-MM-DD_场次名.md          单日
YYYY-MM-DD_DD_场次名.md       跨日
```

## 建议的骨架

| 小节 | 写什么 |
|---|---|
| 一、基本情况 | **计划 vs 实际**两列对照：人数、分组、时长、收费、路演形式 |
| 二、现场做了哪些改动 | 分「✅ 改对了，固化进下一版」和「⚠️ 被迫改，下一版要补防线」 |
| 三、反馈 | 家长原话、学员产出、主讲自评。原话加引号，不转述 |
| 四、必须改的 N 件事 | 每条写成**可执行的动作**，不是「要注意时间」而是「路演硬计时 3+2 分钟」 |
| 五、错过了什么 | 这一节最容易被跳过，也最贵。没采集的数据、没签的同意书、没回收的表 |
| 六、下次回来要问的问题 | 留一个带日期的追问，比如「2026-11：有没有人还在用他自己做的那个东西？」 |
